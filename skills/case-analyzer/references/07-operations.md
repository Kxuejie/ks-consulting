# Operations｜运行型精简框架

## 用途

用于回答“运营表现为什么不达标、真正的瓶颈在哪里，以及如何改善效率、产能、质量或服务水平”。

核心顺序是：**先画清流程并找到卡点 → 解释卡点原因 → 用与原因对应的措施改善**。Reference 约束诊断顺序，不提供通用运营方案清单。

## 标准骨架

1. **了解现状，找到卡点｜Locate the Bottleneck**
   - 业务分类：产品、地域等
   - 生产 / 运营流程
     - 拆分具体流程或运营步骤
     - 评估各环节效率
2. **分析卡点原因｜Diagnose the Cause**
   - 内部
     - 人工效率
     - 技术效率
     - 设备效率
     - 流程环节搭配
   - 外部
     - 消费者 / 需求
     - 供应商
3. **改善问题｜Improve Operations**
   - 内部改善
     - 流程优化
     - 人工效率
     - 技术效率
     - 设备效率
   - 外部手段
     - 收购或增加生产线
     - Outsource 关键流程

## 一、了解现状并找到卡点｜Locate the Bottleneck

### 板块目的

确定问题集中在哪个业务板块、哪个流程环节，以及它如何限制最终产出。不要看到某个指标异常就直接猜原因。

### 业务分类

当公司有多个产品、地域、门店、客户类型或渠道时，先比较：

- 规模与产出；
- 效率、成本、质量或服务指标；
- 与目标、历史或可比单位的差距；
- 对总体问题的贡献。

优先关注“体量重要且差距明显”的板块。题目只涉及单一业务时，删除分类步骤，直接进入流程分析。

### 拆分流程

按真实业务顺序画出投入到产出的关键步骤。根据行业可包括：

- 原材料 / 客户输入；
- 生产、审核、服务或履约环节；
- 等待、搬运与交接；
- 质检、返工或投诉处理；
- 最终交付。

流程粒度以能定位问题为准。不要把每个操作动作都画成独立节点。

### 评估各环节效率

根据题目目标选择指标：

- **制造 / 产能型业务**：Throughput、Cycle Time、Capacity、Utilization、Yield、Defect / Rework、单位成本；
- **服务型业务**：等待时间、处理时长、转化、流失、投诉、一次解决率、人员利用率；
- **物流 / 履约业务**：Lead Time、准时率、损耗、库存周转、单位配送成本；
- **数字化流程**：转化率、响应时间、错误率、系统可用性。

瓶颈是限制整体产出的环节，不一定是单项成本最高或耗时最长的环节。应结合排队、积压、下游空闲和产能约束判断。

### 阶段性总结方向

明确：

1. 问题主要集中在哪个业务板块；
2. 哪个流程环节是核心瓶颈；
3. 该瓶颈主要限制产能、速度、成本、质量还是客户体验；
4. 支撑判断的关键指标。

不要只说“多个环节都有效率问题”。

## 二、分析卡点原因｜Diagnose the Cause

### 板块目的

解释瓶颈为什么发生，并区分内部可控原因与外部约束。原因必须能解释前一部分观察到的具体指标。

### 内部原因

#### 人工效率

检查人员配置、技能、培训、激励、排班、操作差异和错误率。只有指标表明人工环节是限制因素时才展开。

#### 技术效率

检查系统不同步、数据质量、自动化程度、算法或工具是否导致重复工作、错误或等待。

#### 设备效率

检查设备能力、故障、维护、切换时间和实际利用率。高利用率不一定代表高效率；长期接近满负荷可能造成排队和停机风险。

#### 流程环节搭配

检查顺序、依赖、交接、批量大小与质量控制是否合理。常见问题是前后环节能力不匹配、返工路径过长或质检位置不当。

### 外部原因

#### 消费者 / 需求

关注需求波动、旺季峰值、个性化程度和客户输入质量。判断是需求本身超过能力，还是公司缺乏弹性响应。

#### 供应商

关注交付周期、准时率、质量稳定性、最小订单量与单一来源依赖。供应商问题必须与库存、停线、返工或延迟等结果连接。

### 原因验证

优先选择能解释大部分瓶颈影响的 1-2 个根因。可用环节对比、时间趋势、不同班次 / 门店 / 供应商差异或简单的 Input-Output 分析验证。

### 阶段性总结方向

明确核心瓶颈最可能由哪些内部或外部因素驱动、哪个是主因，以及该判断最可能错在哪里。不要把人工、技术、设备、流程全部列成同等原因。

## 三、改善问题｜Improve Operations

### 板块目的

提出与根因一一对应的改善措施，并判断对 Throughput、Cost、Quality 与 Service 的净影响。

### 内部改善

- **流程优化**：取消、合并、重排或简化步骤；调整质检位置或批量大小。
- **人工效率**：针对性培训、标准作业、排班或激励；必要时使用自动化替代重复劳动。
- **技术效率**：改善数据联通、工具、系统或工艺，只展开最能解除瓶颈的升级。
- **设备效率**：维护、换型优化、关键设备升级或增加冗余。

不要只写“提高效率”。每项措施应说明针对哪个根因、改善哪个指标，以及是否会把瓶颈转移到下一个环节。

### 外部手段

#### 收购或增加生产线

适合需求持续超过内部能力、产能是主要约束且新增固定投入具有经济性的场景。检查利用率、投资回收和扩产后需求风险。

#### Outsource

适合外部供应商具备规模、专业或弹性优势，且该流程不是必须内部掌控的核心能力。检查质量、数据 / IP、供应连续性和管理成本。

外部手段不是默认最后答案。应与内部改善在速度、投入、控制、质量和可扩展性上比较。

### 优先级

优先选择：

1. 直接解除主瓶颈；
2. 对关键指标影响大；
3. 实施难度与投入可接受；
4. 不显著损害质量或客户体验。

通常先做低投入的流程与管理改善，再根据剩余缺口决定技术、设备、扩产或外包。

### 阶段性总结方向

明确首选措施、预期改善机制、实施顺序和一项最大反作用。若保留多个方案，必须给主次而不是平行清单。

## Case-specific 使用规则

1. 保留“定位卡点 → 解释原因 → 对应改善”的一级顺序。
2. 所有原因和措施必须回挂到具体流程节点与指标。
3. 业务分类只在多板块差异确实影响诊断时保留。
4. 外部原因不能成为停止分析的理由；仍要判断公司可采取的缓冲或适应措施。
5. 改善措施只展开最关键的 1-3 项，不形成完整 Lean / Six Sigma 教材。
6. 最终 recommendation 先说明瓶颈和根因，再给优先措施、风险和下一步。
