# Pricing｜运行型精简框架

## 用途

用于回答“产品或服务应如何定价、合理价格区间是什么，以及应如何进一步验证和调整”。

核心逻辑是：**先理解定价背景 → 用 WTP 与 Cost 建立上下限 → 用公司目标、监管和竞争缩窄区间 → 管理风险并验证**。

## 一、行业与产品背景｜Pricing Context

### 板块目的

理解公司拥有多少定价权、客户为何愿意付费，以及是否需要按不同产品或客户分层。若 Casebook 已完整给出产品与行业背景，可以压缩本板块，但不能忽略会改变价格上限或竞争定位的信息。

### 行业与产业链

重点判断：

- 公司处于产业链哪个环节，客户和供应商的议价能力如何；
- 市场是高度差异化、相对集中，还是容易发生价格战；
- 牌照、专利、品牌、资本或网络效应是否形成壁垒；
- 监管是否直接或间接限制价格。

行业吸引力不是本题重点。只保留能够解释“公司可不可以收取溢价、价格是否容易被压低”的内容。

### 产品

#### 产品特征与保护

识别客户真正付费的功能、性能、便利性、品牌或服务结果，以及专利、政策或生态是否保护这些价值。

#### 分类

如果不同产品、客户群、地域或渠道具有明显不同的 WTP、成本或竞争环境，应分别定价。分类只保留最有决策意义的 1-2 个维度。

#### 客户需求与习惯

判断：

- 解决的核心痛点有多重要；
- 使用频率、切换成本与替代习惯；
- 购买者、使用者和付款者是否相同；
- 产品优势是否真的能被客户感知。

#### Synergies & Cannibalization

评估新价格对公司其他产品的升级路径、交叉销售与品牌定位的帮助，同时检查是否会挤压现有销量或造成价格体系冲突。

### 阶段性总结方向

明确公司的定价权偏强还是偏弱、最关键的价值来源、是否需要分层定价，以及哪项行业或产品因素最可能约束价格。

## 二、确定价格｜Set the Price

### A. 上限：Willingness to Pay

WTP 是客户因产品获得的价值所能支持的价格上限，不等于公司一定应该收取的价格。

常用方法：

- **替代品法**：以客户下一最佳选择的总成本为起点，再根据产品优劣势调整。
- **经济价值法**：估算产品为客户增加的收入、节省的成本、时间或风险，取其中可合理捕捉的一部分。
- **客户研究**：在有材料时使用调研、历史转化或价格测试结果。

若不同客户的 WTP 差异明显，应先分层再估算，不能用一个平均数掩盖。

### B. 下限：Cost-based

先统一成本与销量口径：

`Unit Cost = Variable Cost per Unit + Allocated Fixed Cost per Unit`

根据题目目标，价格下限可以是：

- 覆盖增量 Variable Cost 的短期底线；
- 覆盖 Total Cost 的长期可持续底线；
- 满足最低 Margin、ROI 或 Payback 要求的价格。

预计销量会影响固定成本分摊，因此成本下限与需求假设相互关联。不得先用高销量压低单位成本，再忽略该价格能否实现相应销量。

### C. 公司目标

公司目标用于在上下限之间选择位置：

- **利润 / 现金流优先**：通常更接近区间上部，但必须检查需求反应；
- **市场份额 / 渗透优先**：通常更接近区间下部，以规模换取未来价值；
- **品牌定位**：高端定位要求价格与产品体验一致，低价可能损害品牌信号；
- **客户迁移或生态目标**：可用基础产品吸引客户，再通过后续服务实现价值。

目标必须明确时间范围。短期渗透价不应被误写成永久价格。

### D. Regulatory Constraints

检查价格上限、最低价、补贴、招标 / 集采、反垄断、公共服务或行业监管。监管要求是硬约束时，应先应用，再讨论公司目标与竞争调整。

不得凭常识编造具体法规；Casebook 未提供且结论依赖时效性监管信息时，将其标为外部验证项。

### E. Competitor Pricing

比较主要竞争者与替代品的：

- 标价与实际成交价；
- 功能、品牌、服务和渠道差异；
- 捆绑方式与收费单位；
- 可能的价格反应。

竞争者价格是市场锚点，不是自动答案。只有明确说明产品的差异化价值，才能合理支持高于竞争者的溢价；低于竞争者也要解释是否来自成本优势或渗透目标。

### 综合定价判断

按以下顺序收束：

1. 建立 WTP 上限；
2. 建立 Cost-based 下限；
3. 应用监管硬约束；
4. 根据公司目标和竞争定位缩窄区间；
5. 给出建议价格或小范围价格带。

如数据允许，说明预期销量、Revenue、Margin 或 ROI。不要只给一个区间而不说明建议落点。

### 阶段性总结方向

明确推荐价格 / 价格带、它在上下限中的位置、主要定价逻辑，以及最关键的销量或 WTP 假设。

## 三、风险与下一步｜Risks & Next Steps

### 风险

只保留最可能改变价格结论的 2-4 项：

- **Elasticity**：涨价导致需求下降超过预期；
- **供需变化**：产能、库存或需求周期改变合理价格；
- **政策变化**：监管、补贴或招标规则变化；
- **竞争反应**：跟价、降价或推出替代产品；
- **内部影响**：渠道冲突、品牌稀释或 Cannibalization。

### 下一步

- **进一步 Segmentation**：识别 WTP 与成本显著不同的客户层；
- **Conjoint / Price Research**：量化客户对功能和价格的权衡；
- **Pilot / A-B Test**：在有限范围验证转化率、销量和 Margin；
- **Dynamic Pricing**：仅在供需、时段或库存差异确实重要时使用；
- **持续监测**：跟踪销量、转化、流失、客诉、竞争价格和利润率。

下一步应优先验证最敏感的假设，不展开成完整研究项目清单。

### 阶段性总结方向

明确建议如何验证价格、什么指标触发调价，以及需要保护的最大风险。

## Case-specific 使用规则

1. 保留“背景 → 上下限与调节力量 → 风险和下一步”的顺序。
2. 背景信息只服务于定价权、WTP、Cost 或竞争定位，不扩展成完整行业分析。
3. 产品分类只有在 WTP、成本或竞争显著不同的情况下保留。
4. WTP、Cost、Competitor Price 必须分清来源，不把竞争价格当作客户 WTP。
5. Casebook 数据不足时给出方向性价格带和关键假设，不编造精确数字。
6. 最终 recommendation 先给价格结论，再给依据、风险和验证动作。
